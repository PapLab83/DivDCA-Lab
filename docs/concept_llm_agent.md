# Концепт: LLM-агент с инструментами (Tool Calling)

## Версия 1.0 | Дата: 2025

---

## 1. Что такое агент в контексте LLM

Агент — это **твой код** который управляет циклом взаимодействия с LLM моделью. Модель живёт на сервере (OpenAI, Anthropic и др.) и ничего не знает о твоём коде. Она только читает текст и пишет текст.

```
Агент = твой код + LLM + инструменты + цикл управления
```

---

## 2. Три ключевых компонента

### 2.1 Системный промпт
Текст который объясняет модели:
- кто она (роль)
- как думать (порядок действий)
- что возвращать (формат ответа)
- чего не делать (ограничения)

### 2.2 Инструменты (Tools)
JSON описания функций которые модель **может попросить вызвать**. Модель не вызывает их сама — она только пишет JSON с именем функции и параметрами. Твой код читает этот JSON и вызывает реальную функцию.

### 2.3 История сообщений (Messages)
Единственная память агента. Растёт с каждой итерацией. Каждый раз отправляется в модель целиком.

---

## 3. Как модель "видит" инструменты

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_prices",
            "description": "Получить исторические цены акций из БД",  # ← модель читает это
            "parameters": {
                "type": "object",
                "properties": {
                    "tickers": {"type": "array", "items": {"type": "string"}},
                    "years":   {"type": "integer"}
                }
            }
        }
    }
]
```

**Модель выбирает инструмент по полю `description`.** Поэтому описание должно быть чётким и однозначным.

## 4. Цикл работы агента

```python
def run_agent(user_message):

    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user",   "content": user_message}
    ]

    while True:

        # Отправляем всю историю + описания инструментов в модель
        response = openai.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools
        )

        # СЛУЧАЙ А: модель хочет вызвать инструмент
        if response.has_tool_calls:

            messages.append(response.message)  # сохраняем намерение модели

            for tool_call in response.tool_calls:
                result = handle_tool_call(tool_call)  # вызываем реальную функцию

                messages.append({                     # сохраняем результат
                    "role":        "tool",
                    "tool_call_id": tool_call.id,
                    "content":     str(result)
                })

            continue  # следующая итерация — модель получит результаты

        # СЛУЧАЙ Б: модель вернула текст — финальный ответ
        else:
            return response.text
```

## 5. Диспетчер инструментов

```python
# Реестр: имя инструмента → реальная функция
TOOLS_REGISTRY = {
    "get_prices":    get_prices,     # идёт в БД
    "calc_sharpe":   calc_sharpe,    # считает метрику
    "calc_drawdown": calc_drawdown,  # считает метрику
    "run_backtest":  run_backtest,   # большой расчёт
    "render_table":  render_table,   # рисует таблицу
}

def handle_tool_call(tool_call):
    name = tool_call["function"]["name"]
    args = json.loads(tool_call["function"]["arguments"])

    func = TOOLS_REGISTRY[name]  # находим функцию
    return func(**args)          # вызываем с параметрами от модели
```

## 6. Как выглядит полный цикл на примере

Запрос: *"сравни AAPL и MSFT за 3 года по Sharpe и MaxDrawdown"*

```
ИТЕРАЦИЯ 1
  → messages: [system, user]
  ← модель: tool_call get_prices(["AAPL","MSFT"], years=3)
  → код вызывает get_prices() → идёт в БД → получает данные
  → messages добавились: намерение модели + результат get_prices

ИТЕРАЦИЯ 2
  → messages: [system, user, assistant, tool(данные)]
  ← модель: tool_call calc_sharpe(AAPL_data)
  → код вызывает calc_sharpe() → возвращает 1.23
  → messages добавились: намерение + результат

ИТЕРАЦИЯ 3
  → messages: [...всё предыдущее...]
  ← модель: tool_call calc_sharpe(MSFT_data)
  → код вызывает calc_sharpe() → возвращает 0.98

ИТЕРАЦИЯ 4-5
  → аналогично для calc_drawdown AAPL и MSFT

ИТЕРАЦИЯ 6
  → messages: [...вся история со всеми результатами...]
  ← модель: возвращает текст с таблицей  ← выход из цикла
```

## 7. Проблема роста контекста и решения

**Проблема:** каждую итерацию отправляется вся история. Контекст растёт → дороже, медленнее, можно упереться в лимит модели.

```
Итерация 1:  500 токенов
Итерация 2:  500 + 300 = 800 токенов
Итерация 5:  уже 3000 токенов
Итерация 10: уже 8000 токенов
```

**Решение 1: Кэш для больших данных**
```python
CACHE = {}

def get_prices(tickers, years):
    data = db.query(tickers, years)
    cache_id = str(uuid4())
    CACHE[cache_id] = data                              # сохранили полные данные
    return {"cache_id": cache_id, "rows": len(data)}   # модели отдали только ID

def calc_sharpe(cache_id):
    data = CACHE[cache_id]   # достали по ID
    return sharpe_formula(data)
```

**Решение 2: Суммаризация старой истории**
```python
def compress_history(messages):
    if count_tokens(messages) > 50000:
        old = messages[2:-4]                    # берём старые сообщения
        summary = llm.summarize(old)            # сжимаем
        messages = [messages[0], summary] + messages[-4:]
    return messages
```

## 8. Разделение агентов по задачам

```
Запрос пользователя
        ↓
[classify_request]  ← простая функция или маленький LLM вызов
        ↓
┌───────────────────────────────────────────────────────┐
│ "сравни метрики"        → Comparison Agent            │
│ "придумай скоринг"      → Hypothesis Agent  (R&D)     │
│ "что купить"            → Advisory Agent    (Prod)    │
└───────────────────────────────────────────────────────┘
```

**Каждый агент имеет:**
- свой системный промпт (роль + правила)
- свой набор инструментов (только нужные)
- общий диспетчер `handle_tool_call`

## 9. Пример системных промптов

### Comparison Agent
```
Ты финансовый аналитик. Отвечаешь на запросы сравнения активов.

ПОРЯДОК ДЕЙСТВИЙ:
1. Получи данные из БД через get_prices
2. Для каждой метрики используй соответствующий инструмент
3. Если инструмента нет — реализуй через execute_python_code
4. Результат оформи через render_comparison_table

ОГРАНИЧЕНИЯ:
- Не придумывай данные
- Не давай рекомендаций к покупке
- Если данных нет — сообщи явно
```

### Hypothesis Agent
```
Ты исследовательский агент. Генерируешь и проверяешь гипотезы скоринга.

ПОРЯДОК ДЕЙСТВИЙ:
1. Получи данные по тикерам
2. Сформулируй логику скоринга (несколько факторов)
3. Реализуй через execute_python_code
4. Проверь через run_backtest
5. Верни: правила + результаты + топ тикеров + ограничения гипотезы

ВАЖНО:
- Документируй логику понятно
- Не утверждай что стратегия сработает в будущем
```

## 10. MCP — когда и зачем

**Без MCP:** описания инструментов прописываются руками в каждом агенте.

**С MCP:** единый сервер хранит все инструменты. Агент подключается и получает нужные автоматически.

```python
# Без MCP
agent = Agent(tools=[get_prices, calc_sharpe, render_table])  # руками

# С MCP
mcp_client = MCPClient("http://твой-mcp-сервер")
tools = mcp_client.list_tools()  # получил автоматически
agent = Agent(tools=tools)
```

**Когда добавлять MCP:**
- инструментов стало 15+
- агентов стало 4+
- чувствуешь боль от дублирования описаний

**Для прототипа — не нужен.** Начни с реестра `TOOLS_REGISTRY`.

---

## 11. Ключевые принципы (из концепции MAS)

```
LLM = генератор идей и диспетчер действий
Инструменты = реальные вычисления и данные
Решения = только через детерминированный слой

LLM не вызывает код напрямую
LLM не принимает инвестиционных решений
LLM не хранит состояние — вся память в messages
```

## 12. Стек технологий

| Компонент | Вариант для старта | Вариант для масштаба |
|---|---|---|
| LLM | OpenAI GPT-4o | Anthropic Claude / своя модель |
| Tool Calling | Нативный OpenAI tools | LangChain / LlamaIndex |
| Реестр инструментов | Словарь TOOLS_REGISTRY | MCP сервер |
| Кэш данных | Dict в памяти | Redis |
| Оркестрация агентов | classify_request() функция | LangGraph / AutoGen |
| Хранение истории | List в памяти | БД + session_id |
