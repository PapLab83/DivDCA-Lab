## Реалистичность: по этапам

### Этап 1: Пет-проект → Проверщик гипотез (100% реалистично)

| Что нужно | Сложность | Риски |
|-----------|-----------|-------|
| Собрать исторические данные | Низкая | Данные есть в открытом доступе |
| Реализовать multi-agent бэктест | Средняя | Чисто техническая задача |
| Показать доходность стратегий | Низкая | Расчеты детерминированы |

**Реалистично:** ✅ Да, это просто инженерная работа. Вы уже спроектировали архитектуру, осталось реализовать.

**Что получается:** Инструмент для себя и других исследователей — "проверь, как бы сыграла стратегия X за последние 40 лет".

### Этап 2: Консультант (советник) — 80% реалистично

| Что добавляется | Сложность | Риски |
|-----------------|-----------|-------|
| Интерфейс для ввода целей (горизонт, риск) | Низкая | Формы ввода |
| Генерация персонализированных рекомендаций | Средняя | LLM может "галлюцинировать" |
| Объяснение решений (почему именно эти бумаги) | Средняя | Нужно хранить rationale |
| Юридическое ограничение (не финансовый совет) | Низкая | Просто добавить дисклеймер |

**Реалистично:** ✅ Да, технически реализуемо.

**Но есть нюанс:** Вы не можете называть это "финансовым консультантом" в юридическом смысле без лицензии. Но как "исследовательский инструмент", "образовательный проект", "помощник для проверки гипотез" — можно.

**Что получается:** Веб-приложение, где пользователь выбирает стратегию (или описывает словами), видит исторический бэктест, получает рекомендации "если бы вы инвестировали в 1980 году, то..." и объяснения.

### Этап 3: Торговец с автоматическим исполнением — 30% реалистично

| Что добавляется | Сложность | Риски |
|-----------------|-----------|-------|
| API-интеграция с брокером (IBKR, Tinkoff и др.) | Высокая | Разные API, безопасность, токены |
| Исполнение сделок | Высокая | Ошибки могут стоить реальных денег |
| Регуляторные требования | Критическая | Лицензии, KYC, AML, отчетность |
| Ответственность | Критическая | Юридические риски |
| Мониторинг в реальном времени | Высокая | Система должна быть 24/7 |

**Реалистично:** ⚠️ Частично, но с большими оговорками.

**Что можно сделать безопасно:**
- **Paper trading** — симуляция торговли на реальных данных без реальных денег
- **Сигналы** — бот отправляет уведомления "купи X", человек сам исполняет
- **Полуавтоматический** — бот готовит ордера, человек подтверждает

**Что НЕЛЬЗЯ делать без лицензии:**
- Автоматическое управление чужими деньгами
- Предоставление инвестиционных рекомендаций как услуга
- Работа с реальными деньгами клиентов

## Реалистичная стратегия "купил и держи" с редкой ребалансировкой

Именно для этого ваша архитектура подходит **идеально**.

### Как это работает:

```python
# Стратегия: купил и держи (buy & hold)
# Ребалансировка: раз в год (или реже)
# Цель: долгосрочный пенсионный портфель

strategy_prompt = """
Ты управляющий пенсионным фондом с долгосрочным горизонтом 20+ лет.
Стратегия: купил и держи.
Ребалансировка: раз в год (в январе).
Цель: максимальный рост с умеренным риском.

Правила:
1. В начале каждого года пересматриваешь портфель
2. Не более 10% в одной компании
3. Не менее 5% в кэше
4. Продаешь только если:
   - Компания показывает ухудшение фундаментальных показателей 3 года подряд
   - Доля выросла выше 12% (продаешь излишек)
   - Компания покинула топ-50 по качеству
5. Покупаешь новые компании, если они входят в топ-20 по качеству
"""

# В оркестраторе:
rebalance_frequency = "yearly"  # или quarterly
```

**Что получается:**
- Низкая торговая активность (низкие комиссии, налоги)
- Стабильный портфель
- AI только для выбора "якорных" позиций
- Детерминированный engine отслеживает дивиденды, сплиты

## Подводные камни (важно для реалистичности)

### 1. Данные — это самое сложное

| Проблема | Решение |
|----------|---------|
| Бесплатные данные (yfinance) могут быть неточными | Использовать несколько источников, проверять |
| Нет данных о банкротствах (survivorship bias) | Использовать CRSP или другие профессиональные источники (платно) |
| Исторические новости сложно собрать | Начать без новостей, только метрики |

**Реалистичный подход:** Начать с **50 компаний из S&P 500, которые существуют до сих пор**. Понять, что это дает bias (выжившие компании), но для прототипа достаточно. Потом добавить данные о банкротствах из бесплатных источников (коммерческие базы).

### 2. Качество LLM-решений

| Проблема | Решение |
|----------|---------|
| LLM может давать странные решения | Логировать, анализировать, дорабатывать промпты |
| Один и тот же промпт → разные результаты | Фиксировать seed, temperature=0, версионировать промпты |
| Высокая стоимость API при частых вызовах | Ребалансировка раз в год/квартал, кэширование |

**Реалистичный подход:** Ребалансировка раз в квартал = 160 вызовов за 40 лет. Стоимость ~$5-10 за полный бэктест (при разумном использовании).

### 3. Юридические ограничения

| Что можно | Что нельзя |
|-----------|------------|
| Называть "исследовательский инструмент" | Называть "финансовый советник" |
| Показывать историческую доходность | Гарантировать будущую доходность |
| Исполнять сделки на демо-счете | Управлять реальными деньгами без лицензии |
| Продавать доступ к платформе как "SaaS для анализа" | Продавать "инвестиционные рекомендации" |
